# Cargo Auctions

SPA для просмотра грузовых аукционов, истории ставок и установки своей ставки. Источником истины для API служит `openapi.auctions.v0.json`; локальный backend заменён stateful-моками MSW.

## Запуск

Требования: Node.js 26.5+ и npm 11.17+. Версии зафиксированы в `.nvmrc`, `.node-version` и `package.json`.

```bash
npm install
npm run dev
```

После запуска Vite выведет локальный адрес приложения. В development-режиме MSW перехватывает запросы к `/api/v1`, поэтому отдельный backend не требуется.

Основные команды:

```bash
npm test           # тесты Vitest
npm run typecheck  # проверка TypeScript
npm run lint       # ESLint
npm run format     # форматирование Prettier
npm run build      # production-сборка
npm run test:coverage # тесты и отчёт о покрытии в терминале и coverage/index.html
npm run generate:api # повторная генерация TypeScript-типов и Zod-схем
```

## Реализовано

- список аукционов с пагинацией, URL-фильтрами, skeleton, empty и error states;
- безопасный разбор search params через Zod и восстановление значений по умолчанию;
- prefetch детальной страницы по intent средствами TanStack Router;
- адаптивные карточки со статусом, маршрутом, параметрами груза, ценой и доступным действием;
- детальная страница с организатором, контактами, точками маршрута, грузом, оплатой и параметрами торгов;
- история ставок с пагинацией, empty state и учётом `hide_bets_history`;
- форма ставки на React Hook Form + Zod с проверками `min`, `max` и `step`;
- обработка backend-ошибок `422`, success/error toast и инвалидация list/detail/bets queries;
- глобальный классовый Error Boundary;
- мобильная панель фильтров на Zustand;
- stateful MSW: успешная ставка меняет текущую/доступную цену, статус участника и историю ставок.

## Маршруты

- `/auctions` — список и фильтры;
- `/auctions/:auctionUuid` — детальная страница;
- `/auctions/:auctionUuid/bets` — история ставок;
- `/auctions/:auctionUuid/bet` — установка ставки.

## Архитектура

Код организован по слоям Feature-Sliced Design:

- `app` — провайдеры, маршрутизация, глобальные стили и обработка ошибок;
- `pages` — композиция страниц;
- `features` — фильтрация, просмотр истории и установка ставки;
- `entities` — API, модели, мапперы и UI аукциона;
- `shared` — API-клиент, сгенерированная схема, конфигурация и общие UI-элементы;
- `mocks` — MSW handlers, изменяемое mock-состояние и fixtures.

Для импортов из `src` используется алиас `@/*`. Относительные импорты сохранены только внутри одного модуля или slice.

Типы DTO генерируются из OpenAPI через `openapi-typescript`. Сетевой клиент дополнительно проверяет каждый успешный ответ и тело ошибки методом Zod `safeParse`. Несоответствие контракта превращается в `ApiContractError`, а штатная HTTP-ошибка — в `ApiError`.

Fixtures — это исходные тестовые данные для MSW: несколько аукционов и ставок с разными статусами и ограничениями. Они позволяют воспроизводимо проверять список, скрытую/пустую историю, недоступную ставку и mutation без настоящего backend. Перед каждым тестом изменяемый mock-store восстанавливается из fixtures.

## Проверка результата

Автоматически проверены:

- разбор URL search params и request builder;
- ViewModel-мапперы карточки, деталей и ставок;
- Zod-схема ставки, включая границы и шаг;
- соответствие API-ответов runtime-схемам;
- фильтрация, пагинация и изменение MSW-store после mutation;
- загрузка списка, error state и восстановление запроса;
- детали и переход к истории ставок;
- успешная ставка, локальная ошибка шага, backend `422` и закрытая форма;
- fallback глобального Error Boundary.


## Допущения и ограничения

- MSW включается только в development. Production-сборка ожидает доступный backend на `/api/v1` либо соответствующий reverse proxy.
- Наличие `.br` в `dist` само по себе не включает сжатие на сервере: hosting или reverse proxy должен быть настроен на раздачу предварительно сжатых ресурсов.
- Состояние MSW хранится в памяти вкладки и сбрасывается после перезагрузки.
- Справочник городов локальный и намеренно небольшой.
- Полноценные E2E и визуальные regression-тесты не добавлены; основные пользовательские сценарии покрыты интеграционными тестами Vitest + Testing Library.
