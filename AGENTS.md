# Рабочие соглашения

## Общие правила

- Пиши минимальный код, который решает задачу.
- Не добавляй лишние абстракции и настройки без явной необходимости.
- Если есть несколько вариантов решения, сначала назови tradeoff, затем выбери самый простой.
- После изменений проверяй проект командой `npm run build`.

## Проект

- Используй Node.js 26.5+ и npm 11.17+.
- Считай `openapi.auctions.v0.json` источником истины. Не изменяй контракт без прямого запроса пользователя и не редактируй сгенерированные API-типы и Zod-схемы вручную; для их обновления запускай `npm run generate:api`.
- Соблюдай Feature-Sliced Design: между slices импортируй через public API и алиас `@`; относительные импорты используй только внутри одного slice.
- Стили компонентов храни рядом с компонентами в `*.module.scss`, глобальные стили — в `src/app/styles/global.scss`.
- На границе API проверяй ответы backend сгенерированными Zod-схемами через `safeParse`.

## Субагенты

- Для сложной задачи с двумя или более независимыми потоками используй субагентов. Простые и последовательные изменения выполняй основным агентом.
- Перед запуском каждого субагента задай ему конкретный результат и непересекающуюся область файлов. Не поручай нескольким агентам одновременно редактировать одни и те же файлы.
- Разделяй ответственность по ролям:
  - **Логика** — API, модели, ViewModel-мапперы, состояние и бизнес-правила; не меняет внешний вид без необходимости.
  - **Интерфейс** — React-разметка и SCSS Modules; не меняет API-контракт и бизнес-логику.
  - **Тесты** — воспроизведение дефекта, тестовые сценарии, fixtures и MSW; production-код меняет только по отдельному поручению.
  - **Ревью** — read-only проверка дефектов, регрессий и пробелов в тестах; возвращает краткие выводы с путями к файлам.
- Основной агент определяет план, объединяет результаты, разрешает конфликты и выполняет итоговые проверки.

## Проверка

- После изменений запускай минимально достаточные проверки из `npm run lint`, `npm run typecheck`, `npm test` и `npm run build`.
- Не сообщай, что проверка прошла, если соответствующая команда не запускалась.
